# 文档治理

英文 Markdown 是实现、上下文恢复和决策的权威来源。中文 *_CN.md 文件是译文。日常工作只更新英文，在获得授权的提交前统一校准翻译。

## 职责与目录

根目录仅保留 README、AGENTS 两组中英文文档。详细文档放在 docs/ 下：

| 文档 | 职责 |
| --- | --- |
| architecture.md | 当前组件、依赖、数据契约及单独标注的目标设计 |
| tasks.md | 当前交付任务与合格性认定缺口 |
| worklog.md | 链接权威文档的简明里程碑索引 |
| development.md | 工程、验证、证据与验收基线 |
| coding.md | 跨语言编码与文件组织基线 |
| style.md | 项目编码差异与工具配置 |
| maintenance.md | 本地流程、故障保证、验证范围与证据限制 |
| segmentation.md | TXT 章节识别与已保留的核验决策 |
| selection.md | 历史技术选型及其假设 |
| proposals.md | 待审核设计 |
| evidence/ | 经筛选并被引用的验证回执和结果 |
| chronicle/ | 冻结的历史记录与完整性元数据 |

每项事实只设一个权威文档。README 和工作日志通过链接引用规范，不重复展开。只有存在独立维护职责时才新增文档。

## 上下文恢复与翻译

依次阅读 [AGENTS.md](../AGENTS.md)、[architecture.md](architecture.md)、[tasks.md](tasks.md)、[worklog.md](worklog.md)，再阅读适用规范和任务契约。日常恢复排除译文及归档证据，任务需要时再读取。

在获得授权的提交前：

1. 比对变更的英文文档与对应中文文档。
2. 对齐含义、标题、标识符、表格、状态、数值限制及链接。
3. 确认每份受维护的英文文档均有译文，且译文没有增加保证或改变要求。
4. 将同步后的成对文档一并提交。存在未决差异时，不得声称翻译已完成。

本检查点不授予提交权限。工作进行期间的差异以英文为准。冻结的历史归档保留原有措辞和字节内容。

## 术语

统一使用下列术语。代码标识符、命令名、协议字段及状态码保持原样。

| 英文 | 中文 | 范围 |
| --- | --- | --- |
| verification | 验证 | 对照明确契约进行检查 |
| validation | 校验 | 检查输入、结构或配置的有效性 |
| acceptance | 验收 | 接受特定范围的交付结果 |
| qualification | 合格性认定 | 判定是否满足工程或发布要求，区别于执行测试 |
| gate | 门禁 | 必需的验收或发布判定 |
| evidence / receipt | 证据 / 回执 | 支撑记录 / 执行结果记录 |
| retain / revoke retain | 保留 / 撤销保留 | 核验操作，沿用已确认的界面名称 |
| read-along | 伴读 | 与音频关联的阅读及控制功能 |
| native host | 原生宿主 | Rust/Tauri 宿主 |

## 归档与证据

里程碑条目保持一至两行。已冻结的工作日志存放于 chronicle/，并保留源路径和 SHA-256 元数据。历史耗时及就绪声明不代表当前测量结果。

[.gitattributes](../.gitattributes)禁止对冻结工作日志进行文本转换；其入库内容必须与已登记摘要一致。

证据按以下规则筛选：

1. 仅提交由 tasks.md、worklog.md、maintenance.md 或 architecture.md 显式链接，用于当前里程碑或缺口闭环的结构化验证回执和最终结果。
2. 排除操作前 ZIP 备份、before/ 等冗余源码快照、动态生成的单次运行目录、原始执行日志及未被引用的中间记录。
3. 原始失败记录及其他必需的诊断材料保留在已声明的本地或受控存储中。移出 Git 不代表允许删除。保留回执中的相对引用可能指向仅本地保存的记录；边界见[维护文档](maintenance_CN.md)。
4. 任务被替代或里程碑归档时，复核关联证据。将过期或不再必要的记录移出追踪，不改写历史执行结果或哈希。

不得忽略整个证据目录，也不得仅凭扩展名准入文件。应按已批准的明确路径暂存。本地未封签回执属于诊断证据，不代表独立的发布批准。
