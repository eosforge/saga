# 维护与本地验证

本文档负责 CLEAN-01（2026-10-20）、REPAIR-01 和 RESIDENT-01（2026-10-23），即已获批准的仓库整理、缺陷修复以及常驻书架目录与进度保存，记录实现契约、本地检查和证据限制。音频播放、同步、其他平台及发布批准不属于该范围。

## 存储与生命周期限制

SQLite 存储书架元数据、阅读锚点及核验指纹。章节元数据与正文存储于归档 `books/<book-id>.saga` 中。暂存文件、备份重命名及立即启动的 SQLite 事务，为单个宿主进程内的常规文件替换与提交失败提供回滚。进程级读写锁覆盖归档读取和修改，但不协调其他进程，也不保证崩溃/断电原子性。恢复本身失败时，错误信息包含所保留备份的路径；提交后清理备份失败会记录日志，不撤销已成功的提交。

已确认的打包规则为：多章分片压缩后的载荷小于 256 KiB。单章压缩后达到或超过 256 KiB 时，仍接受为独立分片，不拒绝、不拆分，也不引入新格式版本。未压缩大小不受 256 KiB 限制。此前的超大单章审核用例使用合成数据，现保留为接受行为的回归测试，不再视为缺陷。检查现有开发书籍时，未发现超限分片。

导入/加载包时，在返回书籍前校验全部已声明正文流及 ZIP 资源完整性。解压上限由声明的正文跨度决定，并非全书内存预算。正文编辑保留资源字节；仅唯一匹配且正文未变的章节保留音频路由。附加资源名称与新生成分片冲突时拒绝编辑。编解码器、时间轴、重复正文的音频匹配及恶意输入的资源预算，尚不在已完成合格性认定的范围内。

SQLite 使用 WAL 和 synchronous=NORMAL。应用在启动时打开并初始化一次受管理的连接。初始化跳过已存在表的创建，仅补充缺失的进度字段，不执行 VACUUM，也不破坏性地删除历史表。现有历史表保持不变。书架目录操作在现有阻塞工作线程上执行，独占访问保留的连接；完整归档操作可能延迟其他命令。此处未对宿主的阻塞工作任务准入队列建立额外上限。测试使用内存数据库或唯一命名的临时数据库，不操作运行中应用的数据库。

播放定时器仅演示句子高亮，不提供 TTS 或真实音频播放。当前纯文本书籍隐藏播放控件。浏览器预览为临时状态，仅支持 TXT。原生书籍加载仍生成全部章节正文，但仅为前五章预先生成分句数组。阅读器移除视口及其外侧 700 px 缓冲区之外的章节，同时至少保留五章。这能限制滚动过程中的持续累积，但不构成严格的 DOM、RSS 或延迟预算；单个大章节仍完整渲染。桌面滚动补偿及长时间会话的内存占用仍需测量。

阅读进度刷新失败时，错误保持可见，当前会话仍可重试。通过阅读器的书架按钮返回及正常关闭处理都会等待保存成功。正常关闭还会在书籍操作进行时保持窗口打开，等待关闭期间阻止进一步的用户交互。卸载、可见性变为隐藏、pagehide 及桌面失去焦点均会请求提前刷新。强制终止、系统关机、生命周期事件遗漏或断电仍可能丢失未保存的位置。自动化生命周期测试不代表真实桌面关闭事件传递或移动端挂起行为已完成合格性认定。

## 常驻书架目录与有界进度保存（RESIDENT-01）

用户在隔离存储比较后批准保留 SQLite，选择 30 秒作为自动保存默认等待时间，并要求设置页提供 5、10、15、30、60 秒选项的滑块。进入后台和正常关闭会提前保存。实现与本地验证记录于 [RESIDENT-01 结果](evidence/2026-10-23-resident/result.json)。范围包括连接所有权、进度调度与生命周期、保存间隔偏好及按需可读导出；该里程碑不授权存储格式迁移、应用启动、提交或发布。

- 应用拥有的单个 SQLite 连接在启动时初始化。阻塞原生操作先取得连接的独占互斥锁，再取得现有归档锁；任何操作都不会递归获取连接。常规错误会释放互斥锁，panic 导致锁中毒后则拒绝后续操作。进度更新复用缓存的预编译语句。原先独立执行的解析仍保持在连接所有权之外。
- 前端按书籍保留最新待保存位置。定时器从首次未保存变更开始计时，不因持续滚动而重置。五个允许的间隔以秒为单位，默认值为 30。界面偏好遵循现有 webview `localStorage` 约定，仅在设置发生变化时写入。已保存值缺失、不可用或不受支持时使用默认值。修改间隔会保留已经经过的单调时间；缩短后的间隔小于已用时间时立即安排刷新。成功写入仅确认已发出的位置，更新的变更继续排队。相同位置不会产生写入，失败的 IPC 响应会使较早的确认失效，失败保持可见且可重试，显式刷新会等待已发出和排队中的写入。
- 返回书架、桌面失去焦点、变为隐藏及正常关闭窗口会请求提前刷新。正常关闭等待保存成功，失败时保持窗口打开。销毁后才完成的监听器注册会被释放。强制终止、操作系统关机、定时器节流、存储阻塞和断电不在计时与关闭保证范围内。
- 设置页在刷新待保存位置后，提供持久化书架元数据、阅读锚点及保留的核验指纹的显式 JSON 导出。原生快照读取共享一个读事务，随后在写入用户选择的 `.json` 目标前释放书架目录连接。同目录暂存文件在常规写入或替换失败时保护现有目标。第 1 版 `saga-library-state` JSON 是诊断导出，不是实时镜像或导入/恢复格式；它不包含归档内容和界面偏好。现有 `.saga` 资产、SQLite 模式、已有 IPC 字段名以及 WAL/NORMAL 设置保持兼容。

验证覆盖常驻连接复用与串行化、SQL 失败、预编译进度更新、虚拟时间调度、未变化锚点、重叠写入与失败、后台/关闭事件顺序与销毁，以及导出内容。已注册的本地检查使用隔离测试数据；真实桌面生命周期和移动端能耗测量尚未完成合格性认定。此前比较属于探索性证据，不构成集成应用性能结论。

2026-10-24 的提交前审核发现，关闭等待进度持久化期间，全局鼠标后退/前进导航仍可切换视图。关闭保护现同时覆盖该处理函数、键盘输入及页面控件。回归测试先复现了阅读器意外切换到书架的行为。[审核结果](evidence/2026-10-24-review/result.json)记录后续验证，不替换原 RESIDENT-01 证据。

## 删除期间的关闭保护（CLOSE-01）

2026-10-24 的后续检查发现，正常关闭仅检查导入/核验忙碌标志，遗漏了待完成的书籍删除。`delete_novel` 响应延迟时，关闭处理会在删除完成前请求销毁窗口。书库现提供同步的 `busy()` 查询，将已有标志与其持有的删除集合结合；关闭处理在刷新进度或销毁窗口前使用此查询。

删除任务的持有状态从等待已发出的进度写入之前开始，并在成功或失败后的现有 `finally` 块中结束。同一本书的重复请求不会释放原任务。完成一次删除不会解除另一本书的删除保护，也不会清除独立的导入/核验操作。只要任一此类操作仍在进行，关闭就保持窗口打开，并提示用户稍后重试；操作完成不会自动关闭窗口。删除失败会保留书籍及排队中的进度，供后续保存。

三个回归测试使用受控原生边界执行真实书架/存储/关闭处理函数，覆盖成功删除与重复关闭、进行中的进度写入结束后删除失败，以及重叠删除与独立忙碌操作。三个测试在旧实现上均先失败。[CLOSE-01 结果](evidence/2026-10-24-close/result.json)记录最终验证和源码身份。真实桌面事件传递及进程退出对数据的影响仍未完成合格性认定；此前证据保持不变。

## 稳定的阅读位置恢复（RESTORE-01）

2026-10-25 的修复将阅读位置采集和恢复统一到同一条基准线，即视口顶部下方 100 CSS 像素。在可滚动范围内，恢复未变化的布局不得推进已保存的位置或段落。恢复过程通过客户端矩形计算滚动增量，不再将元素的 `offsetTop` 当作视口坐标。现有章节/段落/比例字段及存储格式保持不变。

已保存的章节比例仍指向原段落时，保留段内或该段前方间隔中的位置。若重新排版让该比例落入其他段落，则将已保存段落的起始处稍向内对齐阅读基准线；不保证重新排版后的精确字符或段内位置。段落为零且比例为零的锚点会将章节标题保留在顶部。采集和恢复共用段落选择规则，章末空白保留最后一段，不再回绕到第零段。此修复无法重建此前已被覆盖的位置。

七个受控布局回归测试覆盖长首段反复打开、短段落及间隔、不同偏移父元素与视口位置、重新排版、无段间距时仅有段落的锚点、初始/空章节以及章末空白。其中六个在旧实现上失败，初始/空章节用例原本已通过。[RESTORE-01 结果](evidence/2026-10-25-restoration/result.json)记录最终检查和源码身份。这些测试通过模拟布局执行真实阅读器/存储代码；真实桌面渲染及字体/布局行为仍未完成合格性认定。

## 本地检查

[development.json](../development.json) 是由 [tools/check.cjs](../tools/check.cjs) 校验的第 1 版本地反馈注册表，记录组件后果等级、已验证环境、命令及单进程时限（毫秒）。组件分级不代表其验证义务已经满足。

- validate 检查字段、标识、路径、程序、等级及时间上限，不执行检查。
- collect 要求匹配已登记的 Windows x64/工具链标识，并按顺序单次执行每项检查，不下载依赖，不启动应用或服务。
- 每个进程具有时限和 8 MiB 输出上限。Windows 超时清理针对所属子进程树。
- 日志、退出状态、时间戳、哈希及执行前后的源内容清单按唯一的本地运行标识保存。
- 失败、超时、输出不完整或源内容漂移均保留为检查失败。重跑须有已诊断原因、输入变更或其他具体的验证需要。
- 回执为本地未封签记录。哈希可检测意外修改，不是独立的时间戳或签名。

正式模式、审批注册表、义务展开、覆盖率/MC-DC 与变异测试核算、可信采集及发布门禁仍属于 GAP-04。本地运行器不提供具备发布资格的结果。

## 格式与生成文件

Rust 使用锁定的工具链、rustfmt.toml 和严格 Clippy 检查。前端使用已安装的 TypeScript 格式化器，要求命名函数显式声明返回类型，并采用 PascalCase Vue 文件名。在 apps/windows/ 中运行 pnpm format 应用脚本格式，运行 pnpm lint 检查。模板/CSS，以及完整的命名与注释规范仍需审核。

ts-rs 测试从 protocol/src/lib.rs 生成 TypeScript 绑定，不得手工修改。原生生成模式、构建产物、依赖、用户书籍及本地数据不属于手写源码。
