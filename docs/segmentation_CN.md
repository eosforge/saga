# TXT 章节切分

本文是 2026-10-19 授权的 `SEG-01` 修正规范：第225章正文中的编号段落标签，不得在第226章之前生成新章节。范围包括解析，以及用户明确再次导入同一文件时对该书的替换。

## 识别与选择

1. 使用现有编码、标题、引号、元数据及叙事过滤规则，逐行扫描词法候选。保存候选偏移，不复制正文或保存全部行。
2. 在每卷内独立选择标题层级。明确章节（`章`、`回`、`话`、`讲`、`篇`、`Chapter`）优先于小节（`节`、`Section`）、段落（`段`）及纯数字标题，依次降级。
3. 只有不存在明确章节，且较弱层级具有一对编号递增的候选时，才选择该层级。允许缺号，由序列校验继续提示。孤立的弱标签保留为正文。
4. 保留前言、番外、后记及分卷边界。不得为了让校验看起来正常而隐藏真实章节的缺号、重复或重置。明确章标题可以以文学性省略号或逗号结尾。
5. 第二次线性扫描组装章节。被否决的候选行保留原有正文及相对顺序。沿用换行规范化、段落保留和按需分句。识别与组装过程中的进度保持单调。

这是确定性的结构推断。只有数字列表的文档仍可能存在歧义，同卷混用顶层标题与小标题格式也可能需要人工校对。它不承诺所有 TXT 文件都能完美切分。

## 持久化与兼容性

- 公共解析函数签名及序列化的 `Novel`/`Section` 结构保持不变。选中的边界和顺序型章节标识可能变化。
- 重新导入替换同一本书的书架项目，并在 SQLite 中原子替换其元数据和完整章节集合。新解析章节变少时，不会残留旧尾部章节；替换失败则回滚到原书。
- 重新导入会重建章节结构，并替换该文件此前的人工章节编辑。本次改动不会自动重解析或迁移现有数据库与缓存书籍。

## 验证

### 保留与定位（`RET-01`）

用户确认操作名称为 **保留**。该操作只记录核验选择，不改变章标题、章号、正文或阅读顺序。核验页面区分待处理与已处理项目；保留的项目仍可在已处理/全部筛选中查看，并支持 **撤销保留**。书架上的 **核验** 操作可直接重新打开已保存的核验结果，无需重新导入原文件。

- 用户点击保存后，选择才生效。章节与保留记录在同一个 SQLite 事务中提交；保存失败时保留可编辑草稿并显示错误。不保存而跳过或返回时丢弃草稿。可编辑章节/分句对象与撤销快照互相隔离，不可变正文字符串共享。
- SQLite `reviews(book_id, fingerprint)` 将确认记录与章节数据分开存储。指纹包含版本、异常类型/描述、章节位置、当前章及前章内容、同卷同标题章节。相关标题、正文、编号上下文或位置变化会使旧确认失效。同一内容标识书籍的未变重导入保留确认；原文件变化会生成不同书籍标识，不继承旧确认。
- `ValidationAnomaly.key` 与 `retained` 是带反序列化默认值的新增协议字段。阅读器结构报告的含义保持不变：只要存在结构异常，`is_valid` 仍为 false，即使已经保留。原生核验层附加已保存的确认状态。界面将未标记 `retained` 的项目视为待处理；发现编号冲突本身不阻止阅读。
- 后端保存时对照提交章节重新核验请求中的指纹，清除失效确认并向上返回失败。不会自动替用户将原文件或现有书库标记为保留。新增核验表沿用应用的数据库初始化流程创建，不涉及原文重新编号或批量正文迁移。
- 定位使用确切的章节标识，直接跳转到标题本身，不按同名标题匹配，也不回退到已删除章节的旧位置。撤销按当前选中异常所对应的章节位置定位。卷序逆转指向该卷实际首章，而不是第零个章节。

保留状态测试使用隔离数据库，覆盖临时数据库关闭/重开及注入事务失败。前端测试通过模拟 IPC 和 DOM 滚动目标执行实际处理函数。原书测试在内存数据库中独立保留两处已复核重复章号，检查只确认一处时另一处仍待处理，再验证保存及重导入后章节未变。详见[保留功能回执](evidence/2026-10-19-retention.json)。实际 Windows 窗口交互及像素级滚动落点仍待用户审核；这些检查不代表桌面界面验收或正式开发门禁通过。

### 分章验证证据

`packages/reader/tests/segmentation.rs` 覆盖第225/226章案例、嵌套小节与列表、前言、降级格式、孤立标签、分卷格式、真实序列异常、带括号及 CRLF 的标题，以及文学性标点。现有阅读器测试保护解码、句子与段落保留、元数据和进度。

原生内存 SQLite 测试覆盖章节减少的重导入，以及注入插入失败的场景。前端处理函数测试覆盖替换书籍且不重复生成书架条目。命令和结果记录在[验证回执](evidence/2026-10-19-segmentation.json)中；这些是范围内检查，不代表正式开发准入门禁结论。

可选的全书只读测试使用 `SAGA_SAMPLE`，默认测试套件忽略此项。它检查两个段落标签仍在第225章正文中、第226章紧随其后，且原文所有明确的阿拉伯数字章标题均保持原有标题、顺序及出现次数。用户随后提供了原始文件 `D:\texts\修真聊天群.txt`（27,432,041 字节）。最终运行通过：保留全部 3,165 个明确章标题，包括此前漏识别的12个标题；解析得到 16 个卷分组、3,167 个章节条目。一次调试构建解析耗时 211 毫秒；这不是端到端导入延迟测量。

已对照原文复核全部报告冲突。没有警告，只有两处重复章号异常：第2656章在原文第233189、233253行出现，标题不同且正文前后衔接；第2680章同样在第234672、234743行出现。这些是原文件真实的编号冲突，不是误切分或内容重复。每组均保留两个章节及校验提示，不静默删除、合并或重新编号。因此，章节保留测试通过，但校验报告仍正确返回 `is_valid=false`。本次复核没有修改原文件或正在使用的书库。

原始日志及失败记录仅保存在本地。已跟踪回执保留原执行的输入与结果，不承诺全新克隆包含完整诊断材料；存储和回放边界见[维护文档](maintenance_CN.md)。
